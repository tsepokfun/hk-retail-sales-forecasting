## 0. TL;DR（先講結論，後面才是證據）

1. **起點確認**：三種子（42/7/2024）預測集成 **0.94810**，獨立重算完全吻合。逐種子 MASE 平均 0.98355 也吻合。
2. **但 0.94810 是種子樂透的最差一格**。把 5 個種子的所有 3 子集（C(5,3)=10）都算一遍，`{42,7,2024}` 排**第 10（最後一名）**；3 子集中位數 **0.92127**、最佳 **0.89816**。所以「集成 0.94810」不是方法的水準，是抽籤運氣。5 種子集成 0.91230 也沒有比最佳 3 子集好。**增加種子數不是槓桿，種子抽到誰才是。**
3. **超參確實有東西**：`context=24`、`blocks=3`、`embed=64` 三個單維改動，在**同三個種子**上做集成後都顯著贏基準集成（pooled DM p = 0.00016 / 0.0154 / 0.0093；series-level Wilcoxon 在 h=3/h=6 全部 p ≤ 0.004）。其中 **`ctx24` 是唯一連 time-aggregated 檢定（N=12, p=0.034）也過的配置**，證據最強。出貨設定不是最佳設定。
4. **但「哪一個最好」選不出來**：驗證損失與測試 MASE 的秩相關 **ρ = −0.107（p = 0.82，n = 7）**，跨種子時 ρ = 0.30（p = 0.62，n = 5）。事前登記規則挑中的是 `blk3`，測試集最好的是 `ctx24` —— 這兩個是**擲硬幣的兩面**，我不能宣稱任何一個是「選出來的」贏家。
5. **Horizon 門控的假設：依登記規則「部分成立」，但方向是錯的**。門控確實在 h=1 上把污染減半（+0.051 → +0.032），但 `visitor_mtr` 唯一穩定有幫助的視界是 **h=6**（−0.046），而 h=12 —— 假設說它應該有用的地方 —— 只要門打開就**顯著變差**（+0.086，DM p = 0.0023）。淨效果為負。

## 1. 協定、我改了什麼、為什麼

### 1.1 不可改的部分（遵守）

`stage0/eval/harness.py` **一行都沒動**（`git`-free 環境，以下用 mtime/hash 佐證：檔案時間仍是 10/18 21:11，本階段所有腳本只 import 不寫入）。所有指標、DM、MASE 分母、`H.ORIGINS`、`TRAIN_END` 都走原檔。

一律 `purge_val=True`。每一份 meta JSON 都記了 `val_origins` 與 `max_val_target_period`，全部為 `["202112","202212"]` / `202312`（≤ 202312 ✓）。訓練樣本 4,186、驗證 299 與背景相符。

### 1.2 我在 `models/xlstm_direct.py` 做的四處改動（為了一個原因）

**原因**：要做超參網格，就必須能指定 `context / embed / blocks / dropout`。但這四個值在檔案裡被讀了**五個地方**，其中兩個把預設值**綁死在 import 時**：

```python
def make_samples(..., context=CONTEXT, ...)          # 預設值在 def 時綁定 → 永遠是 12
def XLSTMForecaster.__init__(..., embed=EMBED, blocks=BLOCKS, context=CONTEXT, dropout=0.3)
```

所以「從外面改 `X.CONTEXT = 24`」只會改到 `train_model` 的 `first = CONTEXT - 1` 與 `predict_at` 的窗口，**採樣窗口與模型 `context_length` 仍是 12** —— 這正是本專案附錄 A5 記錄的「預設參數綁定」地雷的同一類。與其 monkeypatch，我把它們串成顯式參數：

1. `train_model(..., context=None, embed=None, blocks=None, dropout=None)`，在**呼叫時**解析（`None → 模組常數`），並同時套用到 `make_samples`、模型建構、`predict_at`。
2. `XLSTMForecaster.__init__` 的 `embed/blocks/context/dropout` 預設改為 `None` 並在 `__init__` 內解析（`dropout` 另外拉出模組常數 `DROPOUT = 0.3`，理由同上：signature 預設值會在 import 時凍結）。
3. `forward()` 拆成 `_anchor_terms()` + `_head_delta()` 兩個方法（語意完全相同）。**這是 horizon 門控能做乾淨的前提**：子類只要覆寫 `_head_delta`，就不用複製 anchor 的算術；複製 anchor 等於讓兩個「只差一個變數」的實驗實際上差兩個變數。
4. `train_model` 在 `model_factory` 路徑加**斷言**：模型自報的 `context` / `dropout` 必須等於本次切窗用的值，否則丟 `ValueError`。這正是「factory 忘了串 context」會靜默跑出不同實驗的那種錯。

**改動沒有改變基準**：用新程式碼重跑 seed 42，得到 `MASE_ALL = 1.01743`、`best_val 0.5841 @ ep 31`、anchor 0.8444/0.8464/0.8485/0.8803、參數 20,496 —— 與既有的 `results/exog_meta_z/xLSTM_none_s42.json` **逐位相同**（連 epoch 都一樣）。改成 CUDA 後仍是確定性的。

### 1.3 我在 `models/xlstm_exog.py` 新增的東西

新增 `XLSTMForecasterFiLMHorizon` 與 `selftest_horizon()`（設計理由寫在該類別的 docstring，摘要見 §4.1）。**選的實作**：

```
h       = Backbone(Proj_endo(x_endo) + series_emb)          # 與 `none` 完全相同
pool    = [ x_exog(t) , mean_{t-11..t} x_exog ]             # (2*n_exog,)
gate_k  = tanh(W_g · series_emb_i)[k] ⊙ mask_k              # (embed,)，mask 是 0/1
Δ_k     = head_k( h + gate_k ⊙ Proj_exog_k(pool) )          # 每個頭自己的外生項
yhat_k  = anchor_k + Δ_k
```

**為什麼不是「保留共享投影再加門控」**：任務要求的 selftest 是「改動外生輸入對 h=1/h=3 的輸出**完全不影響**（max abs diff = 0.0）」。只要外生還在共享輸入投影裡，它就一定會改變共享隱藏狀態，h=1/h=3 最多只能做到「差很小」，不可能做到 0.0。所以我把外生**移出**共享投影、只在每個頭前面注入 —— 這是唯一能通過該前提的乾淨實作。骨幹仍然是一個、共享隱藏狀態仍然是一個，三個臂之間只差「外生允許在哪個視界作用」。

`mask_k` 用**結構性乘法遮罩**而不是 `requires_grad=False`（參數切片沒法單獨關梯度）也不是「初始化為 0」：AdamW 的解耦 weight decay 會讓零梯度參數繼續衰減，靠數值不可靠；`0 × 任何東西` 恆為 0。遮罩同時讓閉鎖頭的梯度**恰好為 0**（selftest H5）。

**與 Stage-1 共享投影版的公平性**：兩者的參數增量不同（+4,864 vs +1,344），我照實報，沒有假裝等價。

### 2.3 種子樂透：為什麼「3 → 5 種子」不是一個槓桿

把 5 個種子的**所有**子集都算一遍（`results/stage_h_tableA_subsets.csv`，31 個子集）：

| 4 | 5 | 0.90238 | 0.91243 | 0.92871 |

3 子集排名（10 個全列，`run_stage_h_subsets.py` 原始輸出）：

```
 1. s7,s1,s1234    0.89816
 2. s2024,s1,s1234 0.90111
 3. s7,s2024,s1    0.90970
 4. s42,s1,s1234   0.91086
 5. s7,s2024,s1234 0.92090
 6. s42,s7,s1      0.92164
 7. s42,s2024,s1   0.92429
 8. s42,s7,s1234   0.93237
 9. s42,s2024,s1234 0.93385
10. s42,s7,s2024   0.94810   <- the reported one
```

**結論（這是本次最重要的方法論修正）**：報告目前引用的 0.94810 是 **10 個可能 3 子集中最差的一個**，因為「shipping 種子組」剛好抽到最差種子 42 加上另外兩個中後段的種子。誠實的敘述是：

- 「3 種子集成」的代表值 ≈ **0.921（中位數）**，不是 0.948。
- 集成到 **2–3 個種子就飽和**：最佳 2 子集 0.89543、最佳 3 子集 0.89816、5 種子 0.91230 —— **更多種子沒有更好**，5 種子甚至比最佳 2 子集差。子集間的離散度（≈0.02）大於「加種子」帶來的平均改善。
- 因此 §2.2 的 p = 2.2e-5 只能解讀為「**ENS5 比這一個特定的 ENS3 好**」，不能解讀為「種子數是有效旋鈕」。任何「5 種子 vs 3 種子」的比較都必須說明抽到哪 3 個 —— 這也是我後面比較超參時一律用**同一組三個種子**做配對的原因。

> 附帶：MinT_wls 的 0.94455 是「3 種子集成 + MinT」。既然 3 種子集成本身是抽籤尾端，**0.94455 同樣被低估**；本階段沒有重跑 MinT（見 §7 未做事項）。

| （以上三者在 h=1 / h=12） | 全不顯著 | 全不顯著 | 全不顯著 |

**讀法**：三個超參改動在 **h=3 與 h=6 的 series-level 上都強顯著**（p ≤ 0.004，19–20 條序列裡贏 18–20 條），這比 pooled DM 更有說服力，因為它答的是「是不是大多數零售類別都變好」。但只有 **`ctx24` 連 time-level 也顯著**（N=12 的檢定力很低，能過就是真的穩）。所以：

- **`ctx24` 是全階段唯一在三個獨立檢定（pooled / series / time）下都顯著更好的配置** —— 這是本次最紮實的正向結果。
- `blk3`、`emb64` 通過 series-level，未通過 time-level（power 不足，不能說它們錯，只能說證據較弱）。
- 這也修正了 §3.3 的說法：`blk3` 的 pooled p=0.0154 在 pooled 表裡看起來是第二名，但它的逐視界 pooled p 值（0.059–0.123）與 time-level 都不顯著 —— **它是三個裡最弱的，偏偏是登記規則挑中的那個**。

### 3.4 驗證損失不能當地選器（這是本節最重要的負面結果）

- 測試集最好的是 **`ctx24`（0.90061，DM p = 0.00016）**，但它的驗證損失是**全網格最差**（0.59612），而且是唯一少 276 個訓練樣本的配置。

### 4.3 判讀（依事前登記的規則）

**登記規則**：只有 `visitor_mtr_h12` 的 MASE_ALL **< 0.98355** 才算「長視界專屬外生成立」；落在 0.98355–1.01204 之間只能說「部分修復污染，但淨效果仍為負」；≥ 1.01204 則「假設不成立」。

**結果：`visitor_mtr_h12` = 0.98999（3 種子平均），落在 (0.98355, 1.01204) 中間帶 → 「部分修復了污染，但淨效果仍為負」。**

但逐視界分解把機制講清楚了，而且**推翻了假設的前提**：

| 視界 | none | full（4 頭全開） | h12（h1/h3 關閉） | h1h3（h6/h12 關閉） | 判讀 |
|:---|---:|---:|---:|---:|---|
| h=1 | 0.89161 | 0.94228 (+0.051) | 0.92400 (+0.032) | 0.94338 (+0.052) | 關掉 h=1 的門 → 損害**減少 37%**（+0.051→+0.032）。**這正是假設預測的污染，看得見。** |
| h=3 | 1.07002 | 1.01751 (−0.053) | 1.01913 (−0.051) | 1.02447 (−0.046) | 三個臂都改善，**連 h=3 關閉的臂也改善** → 這不是外生輸入的效果，是骨幹共同訓練的漂移。 |
| h=6 | 1.10963 | 1.06392 (−0.046) | 1.06812 (−0.042) | 1.08036 (−0.029) | **外生唯一穩定有用的視界是 h=6**，不是 h=12。 |
| h=12 | 0.86294 | 0.95145 (**+0.088**) | 0.94870 (**+0.086**) | 0.84264 (−0.020) | **只要 h=12 的門打開就顯著變差（p=0.0023–0.0038）；關掉就回到（甚至略優於）基準。** |

所以：

1. **干擾機制是真的**（「共享隱藏狀態讓只在某些視界有用的變數污染別的視界」）：把 h=1 的門關掉，h=1 的損害從 +0.051 降到 +0.032；把 h=12 的門關掉，h=12 的損害從 +0.088 變成 −0.020。**門控確實能做到「只在允許的視界生效」，selftest 也逐位元證明了。**
2. **但前提（`visitor_yoy`/`mtr_yoy` 是 h=12 的訊號）被推翻**：在**以 `none` 為基準**（而不是以同寬度噪音為基準）時，這兩個變數在 h=12 是**有害**的，唯一穩定有幫助的是 **h=6**。Stage-1 的「h=12 顯著優於同寬度噪音（p≈0.033）」我獨立重算確認無誤（`stage1_exog_dm2.csv`: DM=2.128, p=0.0334）—— 但「贏過噪音」不等於「贏過不用外生」。
3. **淨效果為負**：所有臂的 pooled DM p ≥ 0.53（都不顯著），而 MASE_ALL 最好的是 `h6only` 0.97131（−1.24%）與 `h1h3` 0.97271（−1.10%），**兩者都不顯著**，且都遠不如 §3 的超參改動（−3.4% ~ −5.0%，p ≤ 0.015）。
4. `h1h3` / `h6only` 這兩個「h=12 不碰」的臂都比 `none` 好約 1.1–1.2%，但**都與 `none` 無統計差異**（pooled p ≥ 0.53；series-level 只有 `h1h3` 在 h=3 邊緣顯著 p=0.048；time-level 全不顯著）。它們是事後加的（`h6only` 明確標為探索性），**不得當成確認性結果**。

### 4.4 保守檢定：h=12 的損害是最穩固的統計結論

把 pooled DM 換成兩層保守檢定後，**h=12 上的損害仍然站得住**（而所有「門控變好」的宣稱都站不住）：

| 比較 | pooled DM p（h=12） | series-level（N=23） | time-level（N=12） |
|:---|---:|:---|:---|
| `visitor_mtr_full` vs `none` @ h=12 | **0.0038** | **7 勝 / 16 敗，p = 0.0091** | **1 勝 / 11 敗，p = 0.0034** |
| `visitor_mtr_h12` vs `none` @ h=12 | **0.0023** | **7 勝 / 16 敗，p = 0.0067** | **2 勝 / 10 敗，p = 0.0049** |

三個獨立檢定、兩個損失函數、兩個聚合層級，結論一致：**只要外生門控在 h=12 打開，h=12 就變差，而且 23 條序列裡有 16 條變差、12 個原點裡有 10–11 個變差。** 這不是 pooled 檢定的假象。反過來說，門控臂**沒有任何一格**在 time-level 上顯著變好 —— 淨效果為負是唯一的讀法。

## 6. 結論段（照模板）

> **在我搜過的 14 個訓練配置（30 次 fit）＋ 31 個種子子集裡，最好的是 `ctx24`（context=24）的三種子集成（MASE_ALL = 0.90061，比 0.98355 好 8.43%），這個改善主要來自「超參」，且 pooled DM p = 0.00016（逐視界：h=3 p=0.0045、h=6 p=0.0095、h=1/h=12 不顯著）。**
>
> **這是唯一在三個獨立檢定下都站得住的配置**：series-level Wilcoxon（N=23）h=3 為 20 勝/3 敗 p=0.00013、h=6 為 18/5 p=0.0024；time-aggregated Wilcoxon（N=12）h=3 與 h=6 皆 p=0.034。
>
> **但「最好」不能直接採信為「選出來的」**：`ctx24` 是**唯一驗證損失最差**的配置（0.59612），而且少 276 個訓練樣本；它是**事後用 2024 測試集看出來的**。按事前登記的驗證損失挑選，贏家是 `blk3`（blocks=3）：三種子集成 **0.91612，比 0.98355 好 6.86%**，pooled DM p = 0.0154（power=1 為 0.0024），series-level h=3 為 19/4 p=0.0003、h=6 為 18/5 p=0.0039，**但逐視界 pooled p 值只有 0.059–0.123、time-level 不顯著**，所以它是三個候選裡證據最弱的。驗證損失與測試 MASE 的秩相關 ρ = −0.107（p = 0.82），所以「該挑哪一個」在這份資料上**選不出來**；我能說的只是「這三個單維改動都真的比出貨設定好，其中 `ctx24` 的證據最強、但她不是登記規則選出來的」。
>
> **Horizon 門控的假設：部分成立** —— 依事前登記的判讀規則，`visitor_mtr_h12` 的 MASE_ALL = 0.98999 > 0.98355，落在「部分修復污染、但淨效果仍為負」的中間帶。機制層面成立且可量測（關掉 h=1 的門讓 h=1 的損害由 +0.051 降到 +0.032；關掉 h=12 的門讓 h=12 由 +0.088 變成 −0.020，selftest 逐位元證明閉鎖頭對外生輸入完全不敏感，max abs diff = 0.0）；**但假設的「方向」是錯的**：`visitor_yoy`/`mtr_yoy` 唯一穩定有幫助的視界是 **h=6**（−0.046），而在假設認為它們該有用的 **h=12**，只要門打開就**顯著變差**（DM p = 0.0023–0.0038）。一個只在 h=6 有用的變數，用 horizon gate 綁在 h=12 上是負效果。
>
> **真正撐起「比 0.98355 好」的東西，一半是種子**：報告引用的 0.94810（3 種子集成）是 10 個可能 3 子集中**最差的一個**（3 子集中位數 0.92127、最佳 0.89816）。集成到 2–3 個種子就飽和，5 種子集成 0.91230 並不優於最佳 2 子集 0.89543。**所以「集成」不是槓桿，種子抽到誰才是；真正可複製的改善來自超參（h=6 那個破洞），幅度 3–5%。**
>

## 7. 我沒搜到的維度 / 這次沒做到的事（誠實清單）

### 7.1 任務書要求但我**沒做**的
1. **`context=24` 以外的上下文長度**：只做了 24（`ctx6` 只有程式碼、沒跑）。
2. **`dropout` 的兩個值只跑了單種子**（dp02 / dp05 未補 3 種子）→ **`dp05` 的 +6.75% 劣化是「未證實」**（單種子，且該種子變異大）。
3. **`weight_decay=5e-2` 只有單種子**（1.01906，+3.61%，未證實）。
4. **`MinT_wls` 與 5 種子集成的組合**沒做（0.94455 是「3 種子 + MinT」，而 3 種子本身是抽籤尾端）。
5. **任務書的「8 組新配置」只列得出 6 組**（§3.1）—— 我做了那 6 組，沒有為了湊數捏造配置。

### 7.2 完全沒有進入搜尋空間的維度
- **骨幹**：GRU、TCN、DLinear/NLinear（後兩者由另一個 CPU 子代理在做）、patch-TST、iTransformer、Mamba。本階段完全固定在 xLSTM + `slstm_at=[blocks-1]`。
- **損失函數**：Huber / quantile / log-cosh；`loss_weighted=True`（scale-weighted）在本階段沒掃。
- **優化器細節**：warmup、cosine → step/plateau、grad clip 值、`Adam` vs `AdamW`、`lr ∈ {1e-4, 2e-3, 3e-3}`（只做了 1e-3，且單種子）。
- **`batch ∈ {32, 256}`**（只做了 64，單種子，且它 193 s/fit 是最貴的一格）。
- **`epochs` / early-stopping 規則**：固定 100 epochs + best-val 還原。觀測到最佳 epoch 都在 26–35，代表**後 65 個 epoch 純粹在過擬合**，「早停 + 更短訓練」是一個沒被測的免費可能性。
- **`val_tail`（驗證集大小）**：Stage-3 記錄 `none_k6` = 0.97739 比 0.98355 好，本階段**沒有重驗**（它會改變訓練樣本數與早停點，值得單獨做）。
- **anchor 參數化**：`anchor_init`、`anchor_no_wd`、以及「anchor 的 a_h 在 h=12 學到 0.88 是否過度依賴 persistence」都沒掃。
- **二維互動**：全部 one-at-a-time，**沒有 `context × embed`、`blocks × dropout` 的互動網格**。`ctx24 + emb64 + blk3` 三個一起上會不會相加還是互相抵銷，**未知**。
- **外生變數的其他組合在 horizon gate 下**：只測了 `visitor_mtr`（2 欄）。`all`（8 欄）、`visitor` 單欄、`mtr` 單欄、以及 Stage-1 崩壞最嚴重的 `rain_temp` 都沒在門控架構下重測 —— 特別是「8 欄全部綁在 h=6」值得一試。
- **`h=12` 為何對任何外生注入都敏感**：這是一個診斷問題，需要 per-series / per-origin 誤差分解與 anchor 權重的互動分析，本階段**只描述了現象，沒有解釋**。
- **集成方法**：只做 level 平均與 log 平均；沒做 weighted / median / trimmed mean，也沒做 per-horizon 的加權集成（h=12 的種子間差異最小，理論上該給它更高權重）。

### 7.3 統計上的保留
- 每個 pooled DM 都是**同一組 12 個原點 × 23 條序列 = 276 點**，原點之間高度重疊（h=12 時只有 12 個有效獨立觀測）。pooled DM 我已標為「偏樂觀」，並補跑了 harness 的 series-level（N=23）與 time-aggregated（N=12）Wilcoxon（§3.3b、§4.4）。**time-level 只有 12 個觀測，檢定力很低** —— 它的「不顯著」不能當成「沒有改善」的證據，只能當成「沒有足夠證據」。
- 本階段**沒有做多重比較校正**。我跑了 10 個超參格 × 4 個視界 = 40 個 pooled 檢定，加上 4 個門控臂 × 4 個視界。以 Bonferroni（40 個檢定 → α=0.00125）為標準，**只有 `ctx24` 的 h=3（p=0.0045，未過）與其 series-level（p=0.00013，過了）** 能存活；pooled 的 0.00016 也剛好過。所以「三個超參都好」這個整體結論**在嚴格校正下會退化成「`ctx24` 一個」**。
- 所有「改善」都已附三種子（除 §7.1 明列的單種子格），符合任務書要求；但**單一種子的 `dp02`（−3.91%）、`emb16`（−4.16%）、`lr1e3`、`b64` 一律標為「未證實」**。
- 重複性：本階段兩次跑基準 seed 42（一次前景檢查、一次與其他配置同批）得到**逐位相同的 MASE_ALL = 1.01743**，所以 CUDA 這條路徑是確定性的，表格之間的微小差異不會來自非確定性。
