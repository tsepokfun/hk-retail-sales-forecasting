## ③ 哪些資料能直接擴充現有 23 條序列的面板

實測（`data_external/expansion_scenarios.json`，只計窗內 **200410–202608** 實際存在的數值格）：

| 情境 | 月度序列數 | 月度觀測數 | 相對現狀 |
|---|---|---|---|
| **現狀**：620-67002 價值指數，23 個 outlet type | 23 | **6,049** | 1.00× |
| S1：**補回被漏掉的 outlet type 49** | 24 | 6,312 | 1.04× |
| S2：**＋銷貨量指數 620-67003**（同 outlet type） | 48 | **12,624** | **2.09×** |
| S3：＋超市 4 品類 & 百貨 8 品類（620-67011/67012） | 60 | 15,780 | 2.61× |
| S4：＋餐飲按餐廳類型（625-68004，200801→） | 65 | 16,890 | 2.79× |
| S5：＋網上零售（620-67031，202001→） | 67 | **17,050** | **2.82×** |

### 三個具體併入方式

**(a) 立刻可做、零額外資料：補回 outlet type 49 —— +263 obs（+4.3%）**
`620-67002` 共有 24 個有名稱的 outlet type，現有面板只用 23 個。漏掉的是
**`49` = "Supermarkets and supermarket sections of department stores"**（超市＋百貨內超市部門的合併序列），
在窗內 **263/263 個月全部有值**（`tools/unused_outlet.py` 實證）。
→ 直接多一條序列，且它是**階層上的父節點**（超市 + 百貨超市部門），可用來做階層一致性檢查。

**(b) 最有效：加銷貨量指數 → 面板翻倍 6,049 → 12,624 obs**
`620-67003` 是**同一 25 個 outlet type、同一 200410–202608 月份**的銷貨量指數。
把同一批出口類型的「價值」與「數量」並排，序列數 23→48、觀測數 2.09×，且**沒有任何新月份缺口**（同起同迄）。
研究上可回答：名義銷售成長有多少是價格、多少是實量；也可做 value/volume 的 multi-task 或一致性檢定。

**(c) 擴序列數（換一個產業）：＋餐飲類型 5 條（200801→，1,110 格）**
`625-68004` 的中式/非中式/快餐/酒吧/其他 5 類＋總計。月度只從 2008-01 起（比零售短 39 個月），
但它是**完全不同的需求面**，適合做「跨行業共同因子」或轉移學習的來源。

### 關於「把歷史往前延伸」——必須說清楚

- **做不到**（用 C&SD 零售表）：`620-67001/67002/67003` 三張表在 `full_series=1` 下**全部從 `200410` 開始**。C&SD 官方 index（`WebTableList.json`，590 張表）中 620-* 只有 9 張，沒有一張有更早的月度零售序列。**所以零售面板無法往前延伸到 2004-10 之前。**
- **做得到**（外生變數）：RVD 零售租金指數月度 **1993-01** 起（比面板早 141 個月）、季度 1978Q1 起；訪客到港 200401 起、失業率 198503 起、CPI 197407 起、利率 198001 起、貨運 199701 起。→ 外生特徵的可用歷史遠長於目標變數，可支撐「用長歷史估參數、用短面板訓練」的設計。

## ⑤ 使用前必讀的四個陷阱（都已在檔案中實測）

1. **`215-16004` 的 `freq` 標 `M` 但期間是季度**：實際期間只有 `200603, 200606, 200609, 200612, …, 202606`（只有 03/06/09/12 月，82 期）。若按 `freq=='M'` 過濾會得到假的月度資料。
2. **`210-06101` / `210-06401` 的 `freq` 是 `M3M`**（3 個月移動平均），不是 `M`。直接 `freq=='M'` 會拿到 0 筆。
3. **`620-67002` 的 outlet type `49` 名稱內含 HTML**：`<strong><i><font color="blue">Supermarkets and supermarket sections of department stores</font></i></strong>` —— 若拿 `OUTLET_TYPEDesc` 當 join key 會失敗，要用 `OUTLET_TYPE` 代碼。
4. **年度期間字串會混進月度窗口過濾**：`period` 為 `"2026"`（年度）時，字串比較 `"200410" <= "2026" <= "202608"` 會成立。**任何窗口過濾都必須同時檢查 `freq`**（本 repo 的 `expansion_scenarios.py` 一開始就踩到，修正後 S0 才精確等於 6,049）。
